# Recall implementation report

## Summary

Recall is the second sub-project of Dorothy's memory. Dorothy now searches
and opens her past conversations through a standalone MCP server over a
derived SQLite FTS5 index, appraises what she read in her idle review, and
ranks her memory by salience in place of frecency.

- Spec: [`docs/specs/2026-10-06-recall-design.md`](../specs/2026-10-06-recall-design.md)
- Plan: [`docs/plans/2026-10-06-recall.md`](../plans/2026-10-06-recall.md)
- Branch: `feat/recall`, from `main` at `695610a`

At the head of the branch `bun run check` passes, with 565 tests across 39
files, and a live probe in tmux exercised the whole loop (see
[Verification](#verification)).

The spec is the binding authority and the plan argues from it. Where the
code differs from the spec, the difference is listed under
[Deviations from the spec](#deviations-from-the-spec) with its reason and
what it costs if the reason is wrong.

## How it was built

The plan's 14 tasks were run one at a time. A fresh implementer worked from
each task's text alone. A fresh reviewer then checked the task's diff twice,
once against the plan and spec and once for code quality, before the next
task began. Tasks touching the lock, sync, the service and the conversation
event flow were reviewed on the most capable model.

Three tasks (4, 5 and 10) needed a fix round. In each case the defect was
in the plan's own code, not in its transcription, and the plan's own tests
passed despite it. A ruling from Task 5's review was carried into Tasks 7
and 8 before they were built.
After the last task, a whole-branch review looked at the seams between
tasks, and one further wave of fixes followed it. A scoped re-review checked
every fix round.

Two facts were settled live during the run rather than assumed:

- **The review's structured output** accepts `minItems` and `maxItems`
  above 1. A live review with three pending reads returned three valid
  appraisals. Anthropic's native structured outputs cap `minItems` at 1, so
  this was not a given.
- **Search speed** on a synthetic history of 300 conversations of 80 turns
  each (24,000 turns): the worst case, where every term matches nearly every
  turn, takes about 300 ms. A miss takes about 0 ms, and `open` about 1 ms.

## Deviations from the spec

### Settled in the plan

These were decided while writing the plan. They are listed in the plan's
Rulings section and were carried out as written.

| Spec says                                                                                                                                  | Implementation                                                                                                                                      | Why                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `conversations` has `t_mtime`                                                                                                              | No `t_mtime`. The inode and the indexed byte size decide whether a transcript changed.                                                              | An mtime adds nothing that size and inode do not already tell, and it changes on a rewrite of identical content.                                                             |
| (no counters)                                                                                                                              | `conversations` gains `sessions` and `turns`                                                                                                        | An append resumes numbering visits and turns where the last sync stopped, without re-reading the file.                                                                       |
| `visits.last_at` is `NOT NULL`                                                                                                             | `visits.last_at` may be `NULL`                                                                                                                      | `visitsOf` drops a visit with no valid time. The row is kept while a session is still open, and the query filters it out, exactly as `visitsOf` does.                        |
| `s_mtime INTEGER`, `sidecar TEXT`                                                                                                          | `s_mtime REAL`, and `sidecar TEXT NOT NULL DEFAULT '{"kind":"none"}'`                                                                               | File mtimes carry fractions of a millisecond. A conversation with no sidecar reads as "none", like `readSidecar`.                                                            |
| The open `recall` event records `conversation`, `purpose` and `turns`                                                                      | It also records `name`, the conversation's title when it was opened                                                                                 | A resumed chat shows the same `⌕ opened <title>` line as the live one, even if the title has changed since.                                                                  |

| An `IndexCatalogue` replaces the scan                                                                                                      | A function, `indexCatalogue(index, dir)`, returns the existing `Catalogue` interface                                                                | Same seam and no class needed. `scanCatalogue` and `visitsOf` are removed.                                                                                                   |

### Plan code corrected to match the spec

These are not deviations from the spec. The plan's code fell short of it,
and review caught the gap before later tasks built on it.

| Defect                                                                                                                                       | Spec it broke                                       | Fix                                                                                                                                                                 |
| -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| The index's `-wal` and `-shm` files were created world-readable (0644), and an existing cache directory kept its old mode                    | "mode 0600 in a 0700 directory"                     | The database file is created 0600 before SQLite opens it, and SQLite gives its journal files the same mode. The directory is set to 0700 on every open. (`5bafdef`) |
| Sync listed the transcript directory before taking the lock, then forgot every indexed conversation missing from that stale listing          | "in one `BEGIN IMMEDIATE` transaction"              | The listing moved inside the transaction. (`a27c219`)                                                                                                               |
| A synchronous query could run while another in-process sync was paused at an `await` with its transaction open, and so read half-synced rows | "results are never stale" (sync before every query) | The server's and the catalogue's reads run through the index's in-process queue after syncing. (`02c3703`, `be5d15f`, guarded by `a20bc60`)                         |
| Quitting during a review closed the index before the review released its claim, so the conversation stayed claimed for up to 150 seconds     | "The claim is deleted when the review ends."        | `stop()` returns a promise that settles once in-flight reviews have unwound, and the TUI awaits it before closing the index. (`0ad5c4d`)                            |
| A connection error after a lookup, with a call still pending, lost the reply's `[interrupted]` marker                                        | (the existing chat behaviour)                       | The error marks the reply's last line. (`72d5d0d`)                                                                                                                  |

## Known limitations

Reviewers found these and judged them fine to leave. None blocks merge.

- **A file corrupted after it is opened** is not rebuilt automatically.
  Deleting a shared, live index is what the lock ruling forbids, so it needs
  deleting by hand.
- **A busy open of an index that needs migration** fails after 5 seconds,
  and that launch runs without memory and recall.
- **Search has no row limit** before ranking. That is about 300 ms in the
  worst case at 24,000 turns.
- **Timestamps and indexing.** Window timestamps carry milliseconds
  (`.000Z`). FTS rows key on implicit rowids, so a future `VACUUM` would need
  an explicit key first.
- **Edge cases.**
  - A rare SQLite error that aborts the whole transaction is reported as
    "no such savepoint" rather than the original error.
  - A store test asserts a lock-free open finishes within 100 ms, which may
    be tight on a slow CI runner.
  - `pendingReads` does not deduplicate ids. A transcript with a duplicated
    `open` id would fail every review of it; ids come from the API and are
    unique in practice.
  - `stop()` waits without a timeout for a review that ignores its abort
    signal. The SDK's query honours it.
- **Carried over or outside this spec.**
  - The `user` event is written before the `session` event in a new
    transcript. This predates Recall, and sync matches `visitsOf` as the
    spec requires.
  - The persona still mentions memory tools when the server failed to
    start.
  - Text of hidden conversations stays in the cache index, unreachable
    through the tools.
- **Not fixed here.** The CLI still gives Dorothy Claude Code's auto-memory
  and the account's email address despite `settingSources: []`, which the
  spec leaves to a separate fix. Compaction is the next spec.
