## Verified findings

### P2: URL-scoped Git credential helpers disappear from mirror authentication

Location: packages/memory/src/history/binary.ts:94-95.
Supporting code: isolatedEnv at binary.ts:76-78 disables the user's global config;
credentials at binary.ts:212-220 injects only the helper values returned here.

Trigger: a user has a helper under a URL-specific section, for example
[credential "https://mirror.example"], and no DOROTHY_MIRROR_TOKEN is supplied.
Normal Git resolves this helper for the matching HTTPS mirror. Dorothy only asks
for the exact global key credential.helper, so the scoped helper is omitted.
Since the actual push/fetch shuts out global configuration, Git never gets the
user's helper and cannot authenticate, despite normal Git working for that URL.
This breaks setting/pushing the mirror and recovery from it for a supported Git
credential configuration. Resolve the applicable helper configuration for the
actual remote URL while preserving its scope and helper reset semantics.

Isolated evidence: /tmp/dorothy-review-history-probe.ts writes a temporary global
config containing only a URL-scoped helper. The helper returns synthetic fixture
credentials and writes a temporary marker. A normal git credential fill for that
URL exits 0 and invokes the helper; credentialHelpers with the same env returns
an empty array. No network, actual remote or real credential was involved. The
remaining path is directly established by isolatedEnv and credentials above.
Actual output:

    {"scopedHelper":{"normalGitCode":0,"normalGitInvokedHelper":true,"dorothyHelpers":[]}}

A live authenticated push/fetch was deliberately not exercised.

### P2: A scheduled mirror update is lost while another push is running

Location: packages/memory/src/history/mirror.ts:130-134.
Supporting code: schedule's timer callback clears #timer at mirror.ts:124-126;
launchHistory installs history.afterCommit(() => mirror.schedule()) at
packages/memory/src/memory/open.ts:263.

Trigger: push A has already sealed its snapshot and its network phase lasts
longer than pushMs. A later commit schedules another mirror update; that timer
fires before A finishes. push() returns A's existing #running promise, discarding
the scheduled work. When A finishes it clears #running and schedules nothing.
The last commit remains unsealed and absent from the mirror indefinitely until
another commit or launch, even though the scheduled update elapsed successfully.
Keep a pending/dirty indication or reschedule after the active push completes.

Isolated evidence: the same probe uses a real temporary Git repository and actual
sealing, a deterministic timer map, an injected no-op lock, a synthetic 32-byte key,
and a gated fake repo.push. After push A enters its network phase, it commits a
second change, schedules/fires the timer, then resolves A. Actual output:

    {"scheduledWhilePushing":{"pushes":1,"pendingTimers":0,"unsealedCommitWaiting":true,"sealedBundles":1}}

No remote push was executed. The temporary repository/config/helper directories
are removed by the probe's finally block.

  workflow. No further actionable finding established.
