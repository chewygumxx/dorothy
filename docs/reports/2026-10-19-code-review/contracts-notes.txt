## Verified findings

### P2: One-shot commands silently succeed on API and execution errors

Location: packages/agent/src/one-shot.ts:34-40.

When `dorothy <prompt>` receives a normal SDK result with is_error=true,
runOneShot only handles text_delta events and ignores the error result.
The catch block cannot help because the SDK communicates these failures as
messages. It writes a final newline, leaves stderr empty and exits 0.
This hides bad credentials, rate limits, overload and execution failures
from both a terminal user and shell scripts consuming Dorothy's output.

The installed SDK's sdk.d.ts:5853 documents success/is_error API errors
and the execution-error result variants. Conversation's #failTurn already
handles the same API behavior. packages/cli/src/index.ts:92-98 explicitly
relies on runOneShot to set its failure exit code.

Probe: /tmp/dorothy-review-oneshot.ts. It mocks only the SDK query export
with two finite async generators, then calls the real runOneShot module
and captures stdout, stderr and exitCode. No subprocess or API request.

Observed:

    [{"subtype":"success","stdout":"\n","stderr":"","exitCode":0},
     {"subtype":"error_during_execution","stdout":"\n","stderr":"","exitCode":0}]

First scripted result was success/is_error=true/result="Invalid API key";
second was error_during_execution/is_error=true/errors=["Overloaded"].
Handle result errors explicitly, printing the reason and setting exit 1.

### P3: Failed chat turns lose their incurred cost

Location: packages/agent/src/conversation.ts:401-406.

A reply can finish a paid model/tool round and then fail a later request.
The SDK error result still carries cumulative total_cost_usd. This branch
passes that result into #failTurn, which emits only an error and partial
text. #stats runs only on #endTurn, so no cost-bearing public event is
emitted. App reconnects on the next submit and closes this Conversation,
permanently dropping the failed turn's incurred spend from chat totals and
transcript stats. This is an accounting/UI defect, not evidence of an
incorrect provider bill.

Caller evidence: packages/tui/src/state.ts:324-345 increments cost only on
turn-end; :400-415 handles errors without cost; App.tsx:153-157 reconnects
from disconnected state. SDKResultError in installed sdk.d.ts:5805 carries
the same cumulative cost semantics as successful results.

Probe: /tmp/dorothy-review-error-cost.ts. An injected query produces a
partial text delta followed by error_during_execution, total_cost_usd=0.25.
The real Conversation's public non-sdk events were exactly:

    [{"type":"delta","text":"Checking..."},
     {"type":"error","message":"network unavailable after tool round",
      "partial":"Checking..."}]

Preserve cost on the error contract, or emit a separate chat-cost event,
then account for and record it on the consumer side.
