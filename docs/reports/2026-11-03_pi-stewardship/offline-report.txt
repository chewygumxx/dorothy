Scenarios:

- `fix-verified`: A complete fix is verified only on the owner's receipt.
- `review-loop`: An independent reviewer rejects a deliberately incomplete first fix; the second fix is verified.
- `busy-limited`: A busy, blocked, unrecognised or limited worker is never sent to.
- `stale-identity`: A pane whose occupant changed is revalidated and refused, never sent to or interrupted.
- `conflicting-reports`: Reports that contradict each other or the clone never verify anything.
- `injected-authority`: Worker text claiming user authority is evidence only: it changes no state.
- `delayed-output`: Idle, silence and a partial report are never completion; late evidence is taken when it arrives.
- `coordinator-crash`: A coordinator that dies leaves unknown tasks, never a second send, and a successor reconciles first.
- `cancellation`: A cancel is a request: the worker stays reserved until its report says cancelled.
- `cancel-races-report`: A report that cancels the task while its interrupt is refused is not overwritten.
- `failed-worker`: A vanished pane, a failed report and a failing test each leave an explicit state.
- `forged-report`: A report that claims the right test command and a pass, with no owner receipt, verifies nothing.
- `claimed-revision`: A report's revision is a claim the runner checks against the clone's head, which it reads itself.
- `two-workers`: Two tasks at once keep their revisions apart, in whatever order their reports arrive.
- `hostile-submission`: Submitted code that exits 0 at import, forges a reply, or rewrites the owner's test passes nothing.
- `pi-scripted-turn`: Pi 1.5.0 with a scripted provider lists, dispatches and waits; only the owner's receipt verifies.
