On 2026-10-18 the user ranked what Dorothy's memory must do, in order:
compatibility (any client, harness and model provider), access (the right
memory reachable when needed, from anywhere, and by the user), progressive
disclosure (layers from an always-present core down to raw episodes), and
persistence (durability and history). Every other constraint is
negotiable, "nothing is forgotten" and readable files included. They judge
her current memory weak beside other architectures.

**Why:** a research pass judged replacements by whether they reproduce
Dorothy's own design, so it wrongly found that nothing could replace her
memory; the user corrected it
([the note](../../docs/notes/2026-10-18_open-source-replacements.md)).

**How to apply:** judge memory designs and replacements by these four, in
order, not by parity with the current code, and measure retrieval rather
than assume it. This supersedes the rule in
[Dorothy's ambition](./dorothy-ambition.md) that nothing is forgotten.
